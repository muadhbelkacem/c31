\chapter{Background: Information Extraction and Semantics}
This chapter establishes the theoretical foundations for the "internships-code" system, bridging the gap between Information Extraction (IE) theory \cite{sarawagi2008information} and the practical implementation of a recruitment data pipeline. We explore how semi-structured internship data is transformed into a queryable semantic format, drawing on established principles in data matching \cite{christen2012data}, natural language processing (NLP) \cite{jurafsky2023speech}, and occupational taxonomies.

\section{Information Landscapes: From Unstructured to Structured}
The core challenge in recruitment informatics is the heterogeneity of data sources. Information typically exists on a spectrum of structure, ranging from completely unstructured text to highly structured databases \cite{doan2012principles}.

\subsection{Unstructured vs. Semi-Structured Data}
Unstructured data, such as raw job descriptions or cover letters, lacks a pre-defined data model. Conversely, semi-structured data—prevalent in web-scraped job postings—contains some organizational markers (like HTML tags or JSON keys) but lacks the strict consistency of a relational database \cite{abiteboul1997querying}.

As implemented in the system's ingestion module, web-scraped data often arrives as a "schema-on-read" challenge. For example, while one platform might use the key \texttt{platform\_link}, another uses \texttt{url}. The pipeline must perform \textit{schema mapping} to normalize these into a canonical \texttt{link} attribute.

\subsection{Data Noisiness and Preprocessing}
Web-scraped text is inherently noisy. It contains "boilerplate" (legal disclaimers, navigation links) and formatting artifacts. Data cleaning is a critical prerequisite for reliable extraction \cite{chu2016data}.
\begin{itemize}
    \item \textbf{Text Normalization:} This is the process of transforming text into a consistent canonical form. The system's \texttt{cleanDescription} utility performs basic normalization, which reduces the variance that downstream NLP models must handle.
    \item \textbf{Tokenization:} The first step in most IE tasks is breaking text into discrete tokens. Consistent tokenization is crucial for the dictionary-based matching used in skill extraction and is a fundamental component of information retrieval pipelines \cite{manning2008introduction}.
\end{itemize}

\section{Information Extraction (IE) Fundamentals}
Information Extraction is the automated process of extracting structured information from unstructured or semi-structured machine-readable documents \cite{grishman2015information, sarawagi2008information}.

\subsection{Named Entity Recognition (NER)}
NER is a subtask of IE that seeks to locate and classify named entities mentioned in unstructured text into pre-defined categories \cite{nadeau2007survey}.
\begin{itemize}
    \item \textbf{Dictionary-Based (Gazetteer) NER:} This approach relies on a predefined list of entities. The project's \texttt{extractSkills} function uses this method. While it may miss novel entities, it offers high precision and extreme computational efficiency, making it ideal for the initial stage of a tiered pipeline \cite{nadeau2007survey}.
    \item \textbf{Neural NER:} Modern approaches use sequence labeling models or Transformers to identify entities based on context \cite{lample2016neural, li2020survey}. These are necessary for resolving ambiguities where a word like "Java" could refer to a programming language or a geographic location.
\end{itemize}

\subsection{Slot Filling and Attribute Extraction}
Slot filling involves identifying specific values for a set of predefined attributes (slots) associated with an event or entity.
\begin{itemize}
    \item \textbf{Regex-Based Extraction:} For highly structured attributes like salaries or dates, Regular Expressions (Regex) provide a robust mechanism. The \texttt{cleanSalary} function in the codebase utilizes pattern matching to normalize varied currency strings into a comparable numeric or range format \cite{sarawagi2008information}.
    \item \textbf{Heuristic Validation:} Once extracted, values are often passed through heuristic filters to ensure data integrity.
\end{itemize}

\section{Semantic Categorization and Taxonomies}
Raw job titles and descriptions often suffer from the "semantic gap"—the difference between the specific language used by an author and the general concepts understood by a system \cite{mezzanzanica2019big}.

\subsection{Occupational Taxonomies}
To bridge this gap, systems map raw data to standardized taxonomies.
\begin{itemize}
    \item \textbf{O*NET and ESCO:} Frameworks like O*NET \cite{peterson2001occupational} and ESCO provide a common reference language for the labor market. They organize occupations into hierarchies and link them to required skills.
    \item \textbf{Hierarchical Mapping:} By using a taxonomy, a system can understand professional relationships, such as a "React Developer" being a subset of "Software Engineer" \cite{mezzanzanica2019big}.
\end{itemize}

\subsection{Heuristic vs. Semantic Classification}
While heuristics provide a baseline for "Categorical Filtering", more advanced "Semantic Labeling" involves using sentence embeddings \cite{reimers2019sentence} to find the nearest neighbor in a label space, a method that provides higher recall for idiosyncratic job titles \cite{sayfullina2018learning}.

\section{Record Linkage and Entity Resolution}
When aggregating from multiple job boards, the same internship may appear multiple times with slight variations.

\subsection{Deduplication Strategies}
\textit{Record Linkage} is the task of finding records in a dataset that refer to the same entity \cite{christen2012data, elmagarmid2007duplicate}.
\begin{itemize}
    \item \textbf{Deterministic Matching:} The \texttt{generateId} function uses a combination of "Slugification" and concatenation. This is a form of \textit{blocking}, which significantly speeds up the deduplication process \cite{christen2012data}.
    \item \textbf{Probabilistic Matching:} In cases where names vary, fuzzy string matching is used to calculate a similarity score between records \cite{elmagarmid2007duplicate}.
\end{itemize}

\subsection{Canonicalization}
The final step in normalization is canonicalization—converting a group of linked records into a single "golden" representation, ensuring that the final search index is both concise and accurate \cite{doan2012principles}.
