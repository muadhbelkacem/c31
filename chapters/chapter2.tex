\chapter{Background: Information Extraction and Semantics}
This chapter establishes the theoretical foundations for the "internships-code" system, bridging the gap between Information Extraction (IE) theory and the practical implementation of a recruitment data pipeline. We explore how semi-structured internship data is transformed into a queryable semantic format, drawing on established literature in data matching and natural language processing.

\section{Semi-Structured Web Data and Job Postings}
The ingestion of internship opportunities, as implemented in the \texttt{getInternships} function within the project's data module, highlights the core challenges of semi-structured web data. Unlike rigid relational databases, web-scraped job postings are often delivered as heterogeneous JSON objects or raw HTML.

\begin{itemize}
    \item \textbf{Schema Variability:} As seen in the implementation of \texttt{getInternships}, the system must handle multiple naming conventions for the same attribute (e.g., \texttt{platform\_link} vs. \texttt{link}, or \texttt{date\_posted} vs. \texttt{job\_age}). This reflects the "schema-on-read" nature of modern web data pipelines.
    \item \textbf{Data Noisiness:} Raw descriptions often contain repetitive boilerplate. The system's \texttt{cleanDescription} utility addresses this by removing excessive line breaks and whitespace, a fundamental step in preparing text for downstream NLP tasks.
\end{itemize}

\section{Information Extraction (IE) Fundamentals}
Information Extraction is the task of automatically pulling structured attributes from unstructured text. In the context of the internship portal, this is operationalized through specialized parsing and keyword-matching logic.

\subsection{Skill Extraction}
The \texttt{extractSkills} function in the codebase implements a dictionary-based Named Entity Recognition (NER) approach. By maintaining a curated list of technical and soft skills (e.g., "React", "Python", "Communication"), the system identifies relevant tokens within the job description. While modern deep learning models are available, research demonstrates that structured keyword-based extraction remains a highly effective and computationally efficient baseline for recruitment domains.

\subsection{Slot Filling and Attribute Parsing}
Extracting specific values like salaries requires robust pattern matching. The \texttt{cleanSalary} function utilizes regular expressions to normalize varied currency formats (e.g., converting range strings into a canonical form). This process of "slot filling" transforms descriptive text into filterable metadata, enabling the system's faceted search capabilities.

\section{Semantic Categorization}
To provide a meaningful user experience, raw job titles must be mapped to a higher-level label space. This is critical for overcoming the "semantic gap" where different words describe the same concept.

\subsection{Heuristic-Based Classification}
The \texttt{categorizeJob} function implements a rule-based classifier that maps titles to domains such as "Software", "Data/AI", or "Healthcare". While simple, this approach provides the necessary structure for the system's categorical filtering. As noted by Grijzen, the choice between heuristic rules and complex machine learning often depends on the specificity of the domain and the availability of labeled data; for internship listings, title-based keywords often provide a strong signal for initial categorization.

\subsection{Reference Taxonomies}
In a production environment, these categories can be aligned with international standards like ESCO (European Skills, Competences, Qualifications and Occupations). Aligning the system's internal \texttt{category} labels with these taxonomies ensures interoperability and allows for more granular skill-to-occupation mapping.

\section{Normalization and Entity Resolution}
A significant challenge in aggregating data from multiple platforms is the occurrence of duplicate listings. The "internships-code" project addresses this through a deterministic normalization strategy.

\subsection{Stable Identifier Generation}
The \texttt{generateId} function creates a unique, slug-based identifier by cleaning and concatenating the job title and company name. This technique is a form of \textit{blocking} in the field of entity resolution, where similar records are grouped together to facilitate deduplication.

\subsection{Title Canonicalization}
Standardizing job titles (e.g., removing special characters and converting to lowercase) is essential for both ID generation and search indexing. Javed et al. highlight that generating normalized titles from unstructured text is foundational for downstream analytics, as it allows the system to treat "Software Eng." and "Software Engineer" as the same entity for the purposes of aggregation and discovery.
