\chapter{Methodology and System Overview}
This chapter details the methodology for the lightweight semantic structuring of internship listings. We outline the design philosophy, the architectural components of the pipeline, and the end-to-end data flow that transforms raw web content and file uploads into a structured, searchable knowledge base, based on the implemented Next.js and TypeScript framework.

\section{Design Goals and Constraints}
To address the challenges identified in the recruitment domain, the system is developed with the following primary objectives:

\begin{itemize}
    \item \textbf{Low Computational Cost:} The system utilizes heuristic-based extraction and keyword mapping instead of heavy LLM inference for initial processing, ensuring high throughput and low latency.
    \item \textbf{Robustness to Noisy Text:} The pipeline handles inconsistent formatting from diverse scrapers and user-provided JSONs through dedicated cleaning and validation layers.
    \item \textbf{Explainability:} Extraction decisions (e.g., skill identification) are based on explicit keyword mappings and regex patterns, making the results traceable and predictable.
    \item \textbf{Extensibility:} The TypeScript-based modular design allows for easy addition of new skill keywords or job categories by updating the core libraries.
\end{itemize}

The architecture consists of four main components:
\begin{enumerate}
    \item \textbf{Ingestion Layer (Data Library):} A centralized \texttt{data.ts} module that handles reading from \texttt{intern_data.json} and interfacing with external databases like Supabase.
    \item \textbf{Processing Engine:} A suite of utility functions for cleaning (titles, companies, locations), extracting (salaries via regex, skills via keywords), and categorizing roles.
    \item \textbf{API Layer (Next.js Route Handlers):} RESTful endpoints (e.g., \texttt{/api/internship}) that provide access to processed and cached internship data.
    \item \textbf{Presentation Layer (React/Next.js):} A responsive frontend that consumes the API to display structured listings and facilitate search.
\end{enumerate}

\section{Data Flow}
The data flow within the system follows a linear progression:

\begin{enumerate}
    \item \textbf{Acquisition:} Raw JSON entries are loaded from the filesystem or database.
    \item \textbf{Sanitization and Validation:} The \texttt{isValidInternship} check ensures entries have essential fields. Individual fields are sanitized via \texttt{cleanTitle}, \texttt{cleanCompany}, and \texttt{cleanDescription}.
    \item \textbf{Extraction:}
        \begin{itemize}
            \item \textbf{ID Generation:} A stable, URL-friendly unique identifier is generated from the title and company.
            \item \textbf{Skill Mapping:} The system performs keyword matching against a predefined technical lexicon.
            \item \textbf{Salary Parsing:} Regex patterns extract standardized currency and range information from raw strings.
        \end{itemize}
    \item \textbf{Categorization:} Heuristics map job titles to broad categories (e.g., Software, Data/AI, Design).
    \item \textbf{Caching and Serving:} Processed data is cached in-memory with a TTL (Time-To-Live) to optimize API performance.
\end{enumerate}
