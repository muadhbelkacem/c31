\chapter{Methodology and System Overview}
This chapter provides the architectural blueprint for the lightweight semantic structuring system. By leveraging modern web technologies and a modular backend, the system achieves a performant data pipeline that avoids the latency of external LLM dependencies while maintaining high extraction precision, following established principles in data integration and system design \cite{doan2012principles, buttcher2016information}.

\section{Functional Requirements and Use Cases}
The system is designed to serve two primary actors: the \textit{Student/Job Seeker}, who interacts with the search interface to discover opportunities, and the \textit{System Administrator/Data Engineer}, who manages the automated ingestion and maintenance of the data pipeline. These requirements align with standard practices in recruitment informatics \cite{faliagka2012online}.

\section{The Ingestion Pipeline}
The data ingestion process follows a sequence of operations to ensure raw JSON data is transformed into structured entities, employing techniques for data cleaning and normalization \cite{chu2016data}.

\begin{enumerate}
    \item \textbf{I/O and Safety Validation:} The system reads the source data and performs safety checks to ensure structural integrity \cite{doan2012principles}.
    \item \textbf{Cleaning and Normalization:} Employs specialized logic to handle missing values and noisy text fields \cite{chu2016data}.
    \item \textbf{ID Generation and Conflict Resolution:} Creates stable identifiers to enable deduplication and record linkage \cite{christen2012data}.
    \item \textbf{Semantic Mapping:} Maps extracted information to professional taxonomies like ESCO.
    \item \textbf{State Management:} Utilizes caching strategies to optimize response times and system throughput.
\end{enumerate}
