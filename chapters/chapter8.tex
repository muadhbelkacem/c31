\chapter{Lightweight Semantic Enrichment Pipeline}
The semantic enrichment pipeline is the computational heart of the system, responsible for transforming raw, unstructured text into the structured format defined in Chapter 7. This chapter details the implementation of a high-performance, rule-based extraction engine in TypeScript, designed to minimize latency and eliminate the costs associated with external model inference, following established principles in Information Extraction (IE) \cite{sarawagi2008information, grishman2015information}.

\section{Pipeline Architecture and Data Flow}
The pipeline operates on a "clean-enrich-structure" sequence. Data arriving from web scrapers or manual JSON uploads is first sanitized to remove noise \cite{chu2016data}, then enriched with semantic tags using deterministic heuristics, and finally stored in a structured cache. This layered approach is consistent with production-grade IE systems that prioritize efficiency \cite{boselli2018classifying, menghani2023efficient}.

\begin{algorithm}[H]
\caption{Internship Ingestion and Enrichment}
\label{alg:enrichment_pipeline}
\begin{algorithmic}[1]
\Procedure{EnrichInternship}{rawItem}
    \State $title \gets \text{cleanTitle}(rawItem.title)$
    \State $company \gets \text{cleanCompany}(rawItem.company)$
    \State $id \gets \text{generateStableId}(title, company)$
    \State $desc \gets \text{cleanDescription}(rawItem.description)$
    \State $salary \gets \text{parseSalary}(rawItem.salary)$
    \State $skills \gets \text{extractSkills}(desc)$
    \State $category \gets \text{categorizeRole}(title)$
    \State \Return \text{Internship}(id, title, company, desc, salary, skills, category)
\EndProcedure
\end{algorithmic}
\end{algorithm}

\section{Deterministic Attribute Normalization}
Normalization ensures that the data is consistent and queryable, regardless of the source platform's original formatting \cite{manning2008introduction}.

\subsection{Stable Identifier Generation}
To maintain referential integrity, we implement a deterministic \texttt{generateId} function. This process of creating unique keys for record linkage is critical for data quality in large-scale aggregators \cite{christen2012data, elmagarmid2007duplicate}.
\begin{lstlisting}[language=TypeScript, caption=Stable ID Generation Logic]
function generateId(title: string, company: string): string {
    const slug = (str: string) => str.toLowerCase()
        .replace(/[^a-z0-9\s-]/g, '')
        .replace(/\s+/g, '-');
    return `${slug(title)}-${slug(company)}`;
}
\end{lstlisting}

\subsection{Regex-Based Salary Parsing}
Financial data is often buried within narrative text. The \texttt{cleanSalary} module uses a tiered regex strategy. Pattern matching remains a highly effective method for extracting structured numeric entities from semi-structured text \cite{sarawagi2008information}.

\section{Skill Extraction and Semantic Alignment}
As established in the research objectives, the system must identify professional competencies without the overhead of heavy NLP models.

\subsection{Lexicon-Based Matching}
The \texttt{extractSkills} function implements a case-insensitive keyword search against a curated lexicon. Dictionary-based methods provide a high-precision baseline for entity recognition in specialized domains \cite{nadeau2007survey, nadeau2007survey}.

\subsection{Ranking and Density Control}
To avoid "keyword stuffing," the system employs a density control mechanism. This ensures that the extracted skills represent the core requirements of the role, a common challenge in labor market analytics \cite{giabelli2021skills, bhola2020retrieving}.

\section{Heuristic Role Categorization}
The final enrichment step maps the internship to a high-level domain. The \texttt{categorizeJob} function evaluates the job title against a hierarchy of professional "anchors." This categorization facilitates the efficient discovery mechanisms discussed in retrieval theory \cite{baeza2011modern, croft2010search}.

\section{Caching and Performance Considerations}
To maintain responsiveness, the results of the enrichment pipeline are stored in a server-side cache. This minimizes redundant processing and ensures low-latency performance, a requirement for modern interactive search systems \cite{buttcher2016information, menghani2023efficient}.
