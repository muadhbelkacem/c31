\chapter{Lightweight Semantic Enrichment Pipeline}
The semantic enrichment pipeline is the computational heart of the system, responsible for transforming raw, unstructured text into the structured format defined in Chapter 7. This chapter details the implementation of a high-performance, rule-based extraction engine in TypeScript, designed to minimize latency and eliminate the costs associated with external model inference.

\section{Pipeline Architecture and Data Flow}
The pipeline operates on a "clean-enrich-structure" sequence. Data arriving from web scrapers or manual JSON uploads is first sanitized to remove noise, then enriched with semantic tags using deterministic heuristics, and finally stored in a structured cache.

\begin{algorithm}[H]
\caption{Internship Ingestion and Enrichment}
\label{alg:enrichment_pipeline}
\begin{algorithmic}[1]
\Procedure{EnrichInternship}{rawItem}
    \State $title \gets \text{cleanTitle}(rawItem.title)$
    \State $company \gets \text{cleanCompany}(rawItem.company)$
    \State $id \gets \text{generateStableId}(title, company)$
    \State $desc \gets \text{cleanDescription}(rawItem.description)$
    \State $salary \gets \text{parseSalary}(rawItem.salary)$
    \State $skills \gets \text{extractSkills}(desc)$
    \State $category \gets \text{categorizeRole}(title)$
    \State \Return \text{Internship}(id, title, company, desc, salary, skills, category)
\EndProcedure
\end{algorithmic}
\end{algorithm}

\section{Deterministic Attribute Normalization}
Normalization ensures that the data is consistent and queryable, regardless of the source platform's original formatting.

\subsection{Stable Identifier Generation}
To maintain referential integrity (e.g., for user bookmarks), we implement a deterministic \texttt{generateId} function. By concatenating the slugified title and company, the system ensures that the same listing from different ingestion cycles always maps to the same primary key.
\begin{lstlisting}[language=TypeScript, caption=Stable ID Generation Logic]
function generateId(title: string, company: string): string {
    const slug = (str: string) => str.toLowerCase()
        .replace(/[^a-z0-9\s-]/g, '')
        .replace(/\s+/g, '-');
    return `${slug(title)}-${slug(company)}`;
}
\end{lstlisting}

\subsection{Regex-Based Salary Parsing}
Financial data is often buried within narrative text. The \texttt{cleanSalary} module uses a tiered regex strategy:
\begin{enumerate}
    \item \textbf{Range Capture:} Identifies patterns such as \texttt{\$50k - \$70k}.
    \item \textbf{Unit Capture:} Detects hourly, monthly, or yearly qualifiers (e.g., \texttt{/hr}, \texttt{/yr}).
    \item \textbf{Fallback:} Defaults to "Salary not specified" if no financial tokens are found, preventing UI layout shifts.
\end{enumerate}

\section{Skill Extraction and Semantic Alignment}
As established in the research objectives, the system must identify professional competencies without the overhead of heavy NLP models.

\subsection{Lexicon-Based Matching}
The \texttt{extractSkills} function implements a case-insensitive keyword search against a curated lexicon. While simple, this approach provides high precision for technical domains where terminology is standardized (e.g., "React", "Python", "Kubernetes").

\subsection{Ranking and Density Control}
To avoid "keyword stuffing" (where a recruiter lists 50 technologies to maximize reach), the system employs a density control mechanism:
\begin{itemize}
    \item \textbf{Unique Set Matching:} Uses a \texttt{Set} to ensure each skill is counted only once.
    \item \textbf{Cardinality Limit:} The output is truncated to the top 5 identified skills, prioritizing the first occurrences in the job description which typically represent core requirements.
\end{itemize}

The final enrichment step maps the internship to a high-level domain. The \texttt{categorizeJob} function evaluates the job title against a hierarchy of professional "anchors."

\section{Caching and Performance Considerations}
To maintain responsiveness, the results of the enrichment pipeline are stored in a server-side cache (\texttt{cachedInternships}). This minimizes file I/O and redundant processing. In a production environment, this cache is invalidated every 5 minutes (300,000ms), ensuring a balance between data freshness and system throughput.
