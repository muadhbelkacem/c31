\chapter{Semantic Schema and Label Space}
This chapter defines the internal data model and the controlled vocabularies used to transform raw internship listings into a structured format. We describe the \texttt{Internship} interface used in the implementation and the mechanisms used to bridge the gap between diverse natural language expressions and standardized categories.

\section{Target Schema}
The target schema is implemented as a TypeScript interface, which serves as the blueprint for the extraction and cleaning process. This ensures type safety throughout the data pipeline and provides a consistent structure for the frontend.

\subsection{The Internship Interface}
The core data structure consists of the following fields:

\begin{itemize}
    \item \textbf{Identification:} \texttt{id} (a stable slug generated from title and company) and \texttt{link} (source URL).
    \item \textbf{Organizational Metadata:} \texttt{title}, \texttt{company}, \texttt{location}, and \texttt{platform}.
    \item \textbf{Temporal Attributes:} \texttt{job\_age} (date posted) and \texttt{duration} (length of the internship).
    \item \textbf{Financial and Evaluative:} \texttt{salary} (standardized via regex) and \texttt{rating} (from source platform).
    \item \textbf{Semantic Fields:}
    \begin{itemize}
        \item \texttt{category}: A high-level classification (e.g., Software, Data/AI, Design, Marketing).
        \item \texttt{skills}: An array of extracted technical and soft skill labels.
        \item \texttt{description}: The sanitized job content.
    \end{itemize}
\end{itemize}

\section{Label Space and Categorization}
To facilitate efficient filtering and browsing, the system maps raw job titles to a fixed set of broad categories.

\subsection{Heuristic-Based Classification}
Instead of complex neural classifiers for top-level domains, the system employs a high-performance keyword-based categorization strategy. Job titles are analyzed for specific anchors:
\begin{itemize}
    \item \textbf{Software:} Identified by "developer," "engineer," or "software."
    \item \textbf{Data/AI:} Identified by "data," "analyst," "ai," or "scientist."
    \item \textbf{Design:} Identified by "design," "ux," or "ui."
    \item \textbf{Healthcare:} Identified by "pharmacist," "health," or "medical."
\end{itemize}

\section{Skill Lexicon and Alias Matching}
The semantic "skills" field is populated by matching the job description against a curated lexicon of industry-standard terms.

\subsection{Technical Lexicon}
The current implementation uses a predefined array of keywords covering multiple domains:
\begin{itemize}
    \item \textbf{Languages/Frameworks:} JavaScript, Python, React, Node.js, Java, C++, TypeScript.
    \item \textbf{Data and Cloud:} SQL, AWS, Azure, GCP, Docker, Kubernetes, AI, Machine Learning.
    \item \textbf{Soft Skills:} Communication, Teamwork, Leadership, Management.
\end{itemize}

\subsection{Extraction Logic}
The extraction process uses a case-insensitive search across the cleaned description. To maintain a focused profile for each internship, the system limits the output to the top 5 identified skills. This lightweight approach avoids the computational overhead of Named Entity Recognition (NER) models while maintaining high precision for well-defined technical terms.
