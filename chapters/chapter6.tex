\chapter{Data Collection and Preprocessing}
This chapter describes the data acquisition and preprocessing pipeline implemented in the system. We focus on the ingestion of internship listings from standardized JSON formats and the subsequent sanitization steps required to normalize diverse and often "noisy" input data.

\section{JSON Data Ingestion}
The current implementation utilizes a file-based ingestion system centered around a \texttt{intern_data.json} repository located in the \texttt{public} directory. This approach allows for rapid prototyping and easy integration with external scrapers that output structured JSON.

\begin{itemize}
    \item \textbf{Source Format:} The system expects an array of objects containing fields such as \texttt{title}, \texttt{company}, \texttt{location}, \texttt{salary}, \texttt{description}, and source links.
    \item \textbf{File Handling:} Data is read asynchronously using the Node.js \texttt{fs.promises} API, ensuring that the main event loop remains unblocked during large file operations.
    \item \textbf{Error Handling:} The ingestion module includes robust checks for empty files, invalid JSON syntax, and unexpected data structures (e.g., HTML content served instead of JSON).
\end{itemize}

\section{Data Validation and Integrity}
To ensure the quality of the downstream search and analysis, every entry undergoes a validation check before processing.
\begin{itemize}
    \item \textbf{Mandatory Fields:} The \texttt{isValidInternship} function enforces that every listing must have at least a non-empty \texttt{title} and \texttt{company} name. Entries failing this check are discarded to maintain a high-quality index.
    \item \textbf{Duplicate Detection:} We implement a custom \texttt{generateId} function that creates a stable, URL-friendly identifier by combining the normalized job title and company name. This allows the system to detect and resolve duplicates even when source IDs are missing or inconsistent.
\end{itemize}

\section{Preprocessing and Sanitization}
The \texttt{data.ts} library includes specialized functions to clean and normalize raw text fields:

\begin{itemize}
    \item \textbf{Title and Company Cleaning:} Leading and trailing whitespace is stripped, and "Position/Company Not Specified" placeholders are assigned if fields are missing after cleaning.
    \item \textbf{Description Sanitization:} The \texttt{cleanDescription} function processes the raw job description by splitting it into lines, trimming each line, and removing empty lines. This preserves the structural intent (e.g., bullet points) while removing unnecessary whitespace bloat.
    \item \textbf{Location Normalization:} Similar to titles, locations are trimmed and standardized to handle variations in user input or scraper formatting.
\end{itemize}

\section{In-Memory Caching}
To optimize performance in the Next.js environment, the processed dataset is cached in-memory. The \texttt{getProcessedData} function implements a Time-To-Live (TTL) mechanism (defaulting to 5 minutes), which minimizes redundant filesystem reads and re-processing of the JSON data while ensuring the system stays updated with the underlying data source.
