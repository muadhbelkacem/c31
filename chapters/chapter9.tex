\chapter{Storage, Indexing, and Persistence}
This chapter describes the data persistence and retrieval mechanisms that power the internship search platform. We detail the hybrid storage strategy that combines local file-based data for the internship catalog with cloud-based relational storage for user interactions, as implemented using Next.js and Supabase.

\section{Hybrid Data Storage}
The system adopts a hybrid approach to data management, balancing the speed of local access with the persistence of a managed database.

\subsection{Static Catalog (JSON)}
The primary repository for internship listings is the \texttt{intern\_data.json} file.
\begin{itemize}
    \item \textbf{High-Speed Ingestion:} During server startup or API requests, the system reads this file into memory.
    \item \textbf{Schema Consistency:} The raw JSON is transformed into the typed \texttt{Internship} interface, ensuring that all subsequent operations are performed on structured data.
\end{itemize}

\subsection{Relational Persistence (Supabase)}
For dynamic data and user-specific state, the system integrates with Supabase (a backend-as-a-service built on PostgreSQL).
\begin{itemize}
    \item \textbf{User Management:} Authentication and session management are handled via Supabase Auth.
    \item \textbf{Saved Roles Table:} A dedicated table, \texttt{saved\_roles}, stores the association between \texttt{user\_id} and \texttt{role\_id}. It also persists a snapshot of the \texttt{internship\_data} to ensure that users can view their saved roles even if the underlying JSON catalog is updated.
\end{itemize}

\section{Indexing and Performance Optimization}
To provide a responsive user experience, the system implements several layers of caching and indexing.

\subsection{In-Memory Caching}
The API layer (\texttt{route.ts}) implements a server-side cache for the processed internship data.
\begin{itemize}
    \item \textbf{Cache TTL:} A 5-minute Time-To-Live (TTL) ensures that the expensive operations of reading, parsing, and cleaning 17,500+ records are not performed on every request.
    \item \textbf{Global State:} The \texttt{cachedInternships} variable serves as a high-speed "in-memory index" for the application.
\end{itemize}

\subsection{Client-Side State Management}
On the frontend, the \texttt{useSavedRoles} hook provides an optimized interface for interacting with the persistence layer. It utilizes React's \texttt{useCallback} and \texttt{useEffect} to manage the synchronization between the local UI state and the Supabase database, minimizing redundant network calls.

\section{Retrieval and API Design}
The system's search and retrieval capabilities are exposed via Next.js Route Handlers.

\subsection{Internship API}
The \texttt{GET /api/internship} endpoint serves as the primary data source for the application.
\begin{itemize}
    \item \textbf{Data Transformation:} The endpoint returns the fully enriched and cleaned dataset, including extracted skills and categories.
    \item \textbf{Error Resilience:} The API is designed to fail gracefully, returning an empty array and logging specific error types (e.g., JSON Syntax Errors) instead of crashing the client application.
\end{itemize}

\subsection{Search and Similarity}
While the current implementation focuses on exact filtering, the \texttt{findSimilarInternships} utility in the library provides a foundation for recommendation. It identifies related roles within the processed dataset, facilitating discovery beyond direct search queries.
