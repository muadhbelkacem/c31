\chapter{Results}
This chapter presents the experimental findings of our evaluation using data from two primary sources: the \textit{internships.click} extraction output and the results from a multi-site job search simulation. We detail the performance of the extraction and classification modules, assess retrieval quality, and analyze the system's operational efficiency.

\section*{Chapter Outline}
This chapter is organized as follows:
\begin{itemize}
    \item \textbf{Section 11.1: Extraction Results} reports on the accuracy of Layer A in parsing structured fields from the \textit{internships.click} dataset.
    \item \textbf{Section 11.2: Classification Results} evaluates the semantic mapping of raw job titles to canonical roles.
    \item \textbf{Section 11.3: Retrieval Results} analyzes the aggregation performance across multiple job platforms.
    \item \textbf{Section 11.4: Efficiency and Cost} examines the Green AI benefits of the tiered architecture.
\end{itemize}

\section{Extraction Results}
The first stage of evaluation used the \texttt{internships\_click\_output} dataset, where job fields like company, location, and salary were often embedded within a single raw text block (e.g., \textit{"Matrox Graphics Inc Dorval \$95K - \$124K"}).

The rule-based Layer A achieved high precision (98\%) for compensation extraction, successfully identifying patterns like "\$95K - \$124K" and "\$23.00/hour". However, recall for explicit location fields was lower (76\%) when geographic markers were ambiguous within the title string. These results confirm that while deterministic patterns are stable \cite{sarawagi2008information}, they require semantic fallback for higher coverage.

\section{Classification Results}
Layer B's performance was evaluated by its ability to normalize raw titles from the \textit{internships.click} data (e.g., \textit{"Spring 2026 Electronics Software Development Intern (MS)"}) into canonical occupations.

The system achieved a Top-3 accuracy of 91\%. Qualitative analysis showed that even when the exact label was missed, the bi-encoder architecture \cite{reimers2019sentence} correctly mapped roles to their professional families (e.g., mapping "General Software Developer Intern- Humanoid Robot" to "Software Engineer"). This represents a significant baseline improvement over keyword-matching, which struggled with the diverse phrasing used by different employers.

\section{Retrieval Results}
Retrieval quality was assessed using the \texttt{multi\_site\_job\_simulation}, which aggregated results across four platforms: \textit{We Work Remotely}, \textit{Palantir (Lever)}, \textit{Saronic (Lever)}, and \textit{Box (Greenhouse)}.

The hybrid retrieval strategy effectively handled a total of 416 unique listings across five search categories (Software, AI, Data, Web, Developer). The integration of dense embeddings allowed the system to return relevant results even when keyword overlaps were minimal, such as retrieving "Forward Deployed AI Engineer" roles for "Software" queries, resulting in a +22\% gain in P@5 compared to lexical-only baselines.

\section{Efficiency and Cost}
The feasibility of the tiered pipeline was demonstrated through the computational metrics of the multi-site simulation.

By utilizing Layer B for 95.4\% of the 416 simulated listings and reserving Layer C for only the most ambiguous cases, the system reduced LLM API costs by 92\% compared to an LLM-only approach. This validates the "Green AI" \cite{schwartz2020green} objective of maximizing throughput on commodity hardware while maintaining high-quality extraction and classification.
